这个博客从第一天起就是自己写的：一个 `index.html`，一套极简的 Markdown 规则，外加一个后台编辑器。好处是轻，没有任何构建步骤，改完刷新就能看；坏处也很实在——它长期只装得下「文字 + 图片」。

想放一段录屏，只能贴个外链；想放一首歌，得去第三方播放器；想并排看几张图，得手写 HTML。久而久之，文章里本该有的东西，被工具的短板削掉了一半。

所以这次干脆把编辑器重做了一遍。**你现在读的这篇文章，本身就是用新组件写出来的**，往下翻可以一个个看到实际效果。

> [!TIP]
> 文中的视频、动图、音频都能直接点开——图片和动图点一下是放大看原图，视频自带控制条，右上角还有个放大按钮。

## 一、视频：不再只能贴外链

最直接的改变：本地视频可以直接插进正文。

![示例片段（CC0 素材）：点右下角可以拖进度](demo.mp4)

不用记路径，也不用先做封面。编辑器会自己读时长、贴角标、按真实比例占位——竖屏录屏不会被人为裁成横的。要是文件没上传成功、或者文件名写错了，它会明明白白告诉你「这个视频没能加载」，而不是留一块沉默的黑。

> [!NOTE]
> 上面这段是按公开的 CC0 素材放的示例，只是为了让你能真的点一下播放器。你自己的录屏，把文件丢进同一个文件夹，写一行 `![说明](文件名.mp4)` 就行。

## 二、动图：会动的画，不该有暂停键

动图和视频在语法上是两回事。视频是「一段可以控制的东西」，动图是「一张会动的画」。

所以动图**没有控件、不能暂停、静音循环**：滚出屏幕自动停，滚回来接着放。省电，也不会在你往下滑的时候突然冒出一串声音。想看细节就点一下，进大图慢慢看。

@motion[同一段素材，按动图的方式播放：无声、循环、没有进度条](loop.mp4)

> [!NOTE]
> 它以前点一下会暂停——这是个明显的语义错误，「会动的画」被当成了播放器。这次一起改掉了。

## 三、音频：一张安静的卡片

@audio[阿拉斯加海湾 - 蓝心羽](bgm.m4a)

音频不占满整行，收成一张小卡片，带标题和来源标签。它看起来最不起眼，但这次的坑恰恰出在它身上：

**进度条怎么点都不动。** 查了半天样式、层级、事件拦截，结果跟这些都没关系——服务器返回这个 `.m4a` 时没有带 `Accept-Ranges`，浏览器读到的可跳转区间是 `0 ~ 0`，等于告诉播放器「这段只能从头播到尾」。文件其实早就下完了，但拖不动就是拖不动。

现在的处理是：一旦检测到这种「不可跳转」的状态，就把整段数据转成 Blob 再挂回播放器，拖动立刻恢复。数据本来就在 HTTP 缓存里，几乎不额外花流量。

## 四、链接、附件：两种「不是图片的东西」

以前的链接就是一行蓝字，附件只能甩个网盘地址。现在它们各有各的样子：

@link[鉴业の小站](https://jianye.pages.dev/ "个人博客 · 记录折腾过的一切")

链接卡会按域名生成固定的颜色，同一个站点永远是同一个色块；有标题有描述，比裸地址体面得多。

@file[这次更新的完整说明（Markdown）](更新说明.md)

附件卡显示扩展名色块和原始文件名，点一下直接下载。压缩包、说明书、表格都走这一个样式。

还有 `@embed[...](B站 / YouTube / Vimeo 链接)`：认出平台就换成播放器，认不出的站点自动退化成链接卡，不会留一个空白框。这篇里没放，是因为我不想塞一个别人的视频进来充数。

## 五、图集：几张图并排看

@gallery[shot-list.png, shot-post.png, shot-mobile.png]

两到四张图自动分栏，窄屏上降为两列，每一张都能点开看原图。上面三张是这个站现在的样子：文章列表、文章页、手机端——同一套渲染，三种宽度。

## 六、提示块：给重点一个颜色

有些话不适合埋在段落里，需要有块状的存在感。GitHub 那五种写法都支持：

> [!IMPORTANT]
> 重要的结论放这里——扫读的人一眼就能看见。

> [!WARNING]
> 会让人踩坑的地方放这里，比如「删之前先备份」。

> [!CAUTION]
> 比警告更严重的东西：不可逆的、会丢数据的。

颜色和图标各不相同，写起来只是 `> [!TIP]` 加一行内容，不用记 HTML。

## 七、待办清单：真的能打勾

- [x] 媒体：视频 / 动图 / 音频
- [x] 内容块：链接卡 / 附件卡 / 图集
- [x] 提示块与待办清单
- [x] 图片、视频、动图点开放大
- [ ] 给图片补一个图注
- [ ] 把更新日志做成独立页面

上面这几个勾是能点的。在站点上点，状态记在浏览器本地，不会改动文章文件；在编辑器的预览里点，会直接改回正文，保存之后就真的写进 `index.md` 了。

## 八、排版：对齐、表格、代码

|c 这一行是居中的，用工具栏上那组左 / 中 / 右按钮点出来

|c 以前「居中」被塞进了「插入」面板里——选中文字想居中，得去插入菜单里翻，逻辑上就是错的。它现在回到了文字格式组，和加粗、斜体摆在一起。

| 能力 | 语法 | 说明 |
| --- | --- | --- |
| 视频 | `![说明](x.mp4)` | 带控制条，可放大 |
| 动图 | `@motion[说明](x.mp4)` | 无声循环，不可暂停 |
| 音频 | `@audio[说明](x.m4a)` | 小卡片，可拖动 |
| 链接卡 | `@link[标题](url "描述")` | 按域名取色 |
| 附件 | `@file[名称](x.zip)` | 直接下载 |
| 图集 | `@gallery[a.png, b.png]` | 2 到 4 张 |
| 提示块 | `> [!TIP]` | 五种样式 |
| 待办 | `- [ ]` | 可勾选 |

> [!NOTE]
> 对齐没进这张表，是因为它的语法里带一个竖线，写进表格会把表格切开。行首写 `|c 文字` 就是居中，`|l`、`|r` 同理——上面那两段居中文字就是这么来的。

代码块照旧：

```javascript
const blocks = ["video", "motion", "audio", "gallery"];
blocks.forEach(kind => console.log(`已支持：${kind}`));
```

> 引用块还是原来的样子，左边一条竖线，字稍微淡一点——适合放一句摘录，或者一段不该被略过的话。

## 九、编辑器本身

界面这轮全部对齐了站点的视觉：同一套配色、同一块玻璃质感的浮动导航、同样的圆角语言。写着写着，不会突然觉得自己在用一个陌生的后台。

手机上原来是「把桌面界面缩小塞进去」，现在是真的重新排过：分成「正文 / 素材 / 设置」三栏切换，工具栏可以横向滑动，最要紧的保存按钮固定在底部，键盘弹起来也不会把它盖住。

中英双语和站点共用同一个开关，切一次，两边一起变。

顺便，那个摆在最显眼位置、却**从头到尾没有绑定过点击事件**的「💾 保存到本地」按钮，这次也终于能用了。这种按钮最要命：它看起来完全正常，你写完点一下，什么都不会发生，然后你以为保存了。

## 十、这次挖出来的九个问题

| 症状 | 真正的原因 |
| --- | --- |
| 点预览整页卡死 | 渲染主循环空转：某一行谁都不要，又没往前走 |
| 手机 → 平板 → 桌面切换忽然硬切 | 同时动画两个宽度属性，取最小值时被单侧夹住 |
| 动图能被暂停 | 残留的暂停蒙层没删干净 |
| 图片、视频不能放大 | 灯箱只服务相册，没接正文 |
| 待办打不了勾 | 渲染时写死 `disabled`，CSS 还加了 `pointer-events:none` |
| 保存按钮没反应 | 事件压根没绑 |
| 媒体库出现两份 | 三处并发刷新，同一批文件被重复塞进数组 |
| 音频进度条拖不动 | 服务器没返回 `Accept-Ranges`，可跳转区间是零 |
| 手机端切设备没变化 | 三个档位都被面板宽度夹成了同一个数 |

列在这里，是因为它们大多不是「写错了」，而是「看起来对、其实没生效」——只有真的点一遍、拖一遍才会暴露。

## 写在最后

改动全部落在两个文件里：`index.html`（站点与渲染器）和 `admin/index.html`（编辑器）。没有构建流程，没有依赖，改完就是改完了。旧版本留了备份，随时可以整文件回退。

> [!TIP]
> 如果你也在用自建的静态博客，我的建议是：先把「写」这条路修平。工具顺手了，才愿意多写。反过来，一个保存按钮失灵，足以让人一整晚都不想打开它。
